**日期**：2026-10-09  
**状态**：完成

已完成 WPF 桌面应用、服务与 ViewModel headless 测试，以及 README 和设计文档同步。统一 Debug/Release solution 构建均为 0 警告、0 错误；Release 全量测试 306 项通过（Core 277、App 29），0 跳过、0 失败。测试覆盖取消按钮 `CanExecuteChanged` 通知：计划生成挂起时通知 UI 可取消，取消后服务收到令牌并回到空闲。人工渲染检查覆盖 1320×860 标准尺寸和 1020×650 紧凑尺寸；紧凑布局滚动后可完整查看文件表、冲突选项和确认复选框。预览使用 mock service，未执行真实扫描、游戏写入或游戏启动。
**范围**：为 Plan A/B 的 Core 与 CLI 增加 Windows WPF 前端，不引入提权 Worker、在线下载或启动后健康检查。

## 目标

用户能够在桌面界面中扫描和选择游戏、选择实际部署的 exe 与 Profile、查看体检结果和完整部署计划，在明确确认后部署，并查看历史记录或安全回滚。所有写入仍由 Plan A Core 执行；UI 在计划失效、台账损坏、目标阻塞或需要尚未实现的提权时必须阻止 Apply。

## 实施任务

- [x] 建立独立的 `net8.0-windows` WPF `Deployer.App`，保持 Core 为 `net8.0`。
- [x] 实现应用服务适配层，将扫描、检查、规划、部署、回滚、Profile、手动目录和台账 API 提供给 MVVM。
- [x] 实现游戏选择、exe/Profile/帧生成设置、体检与计划审阅、确认部署、历史回滚和错误诊断页面。
- [x] 计划输入改变时清除旧计划及确认；阻塞警告、未知/需提权、未解决身份冲突、损坏台账时不得执行。
- [x] 异步操作支持取消并忽略过期结果；取消部署时保留准确的取消结果与恢复清单，未提交新计划时不覆盖既有台账。
- [x] 为 ViewModel 与应用服务增加无头测试，覆盖确认边界、计划失效、损坏数据保护、回滚与台账一致性。WPF View 自动化不在范围内。
- [x] 更新产品 README、设计文档和本计划，记录构建与测试证据。

## 验收边界

- Release 与 Debug 均能构建；测试运行在 `net8.0-windows`，不要求创建 WPF View 或启动桌面窗口。
- 至少一条端到端用例只在测试专属临时目录创建游戏与 payload，完成 Plan → Apply → Rollback，并逐字节核对文件及目录恢复。
- App 测试不得引用或修改真实游戏目录；所有临时目录带唯一 GUID，并在清理前验证其直接父目录和 GUID 名称。
- Plan A/B 已通过的行为保持兼容，C 不把 Plan D 能力描述成已提供。
